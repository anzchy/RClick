# RClick signed release, the short way

Goal: tag pushed, workflow green, notarized DMG and zip in a DRAFT release, owner tests and presses Publish. The owner does only what needs their Apple login or an OS prompt; the delegator does the rest. This is the flow that produced the v2.3.5 draft.

Rules: never print or log a secret value; fork `anzchy/RClick` only (`gh ... -R anzchy/RClick`); no scratch file with a key or password may outlive the step that needs it. Tag rules: once a release, draft or artifact exists for a tag, never delete, move or reuse it. A tag whose run failed BEFORE Create Release made anything (no release, draft or artifact) may be deleted and re-pushed once, only with the owner's explicit approval (v2.3.5 was, 2026-11-24). Re-running a failed run is allowed only if it failed before Create Release and the tag commit already holds the workflow you want; it reuses the tag's commit and workflow file.

## How RClick signs
Workflow builds unsigned (`CODE_SIGNING_ALLOWED=NO`), signs layer by layer with the Developer ID Application identity, and embeds two Developer ID provisioning profiles (app `cn.anzchy.RClick`, extension `cn.anzchy.RClick.FinderSyncExt`) because both processes are sandboxed and share `group.cn.anzchy.RClick`. The workflow validates each profile (bundle id, team `GRT84NAK4T`, the group, and that its certificates contain the signing identity). Xcode's "Mac Team Provisioning Profile" files are development profiles and do not pass. Notarization uses Apple ID + app-specific password through `scripts/release/notarize.sh` (no App Store Connect API key). Changing the App Group id to avoid profiles is a product change: not for a release.

## Secrets (all required; `gh secret list -R anzchy/RClick` shows names and times only)
| Secret | Value | Who |
|---|---|---|
| `APPLE_ID` | Apple ID email of the developer account | owner, `gh secret set APPLE_ID -R anzchy/RClick` |
| `APPLE_APP_SPECIFIC_PASSWORD` | app-specific password (account.apple.com → Sign-In and Security) | owner, from the clipboard: `pbpaste \| tr -d '[:space:]' \| gh secret set APPLE_APP_SPECIFIC_PASSWORD -R anzchy/RClick`, then `pbcopy < /dev/null` |
| `APPLE_TEAM_ID` | `GRT84NAK4T` | delegator |
| `MACOS_CERT_P12`, `MACOS_CERT_PASSWORD` | Developer ID Application `.p12` (base64, single identity) and its password | delegator exports; owner clicks the keychain prompt |
| `MACOS_APP_PROVISIONING_PROFILE`, `MACOS_EXTENSION_PROVISIONING_PROFILE` | Developer ID profiles, base64 | delegator, via Xcode CLI |

`KEYCHAIN_PASSWORD` is a fixed string inside the workflow, not a secret. Pitfall seen: a secret typed or pasted into an interactive `gh secret set` can be saved EMPTY (the run then fails with `Missing notarization environment: APPLE_APP_SPECIFIC_PASSWORD`; empty values show as blank in the step's env block, set ones as `***`). Use the clipboard form above.

## Steps
1. **Diagnose.** `gh run view <id> -R anzchy/RClick --log-failed`; read the step env block for blank secrets; `gh secret list`. Passing guards (tag, version, notes) before the failed step mean the tag is fine. `SecKeychainItemImport … not valid` = missing or empty `MACOS_CERT_P12`/`MACOS_CERT_PASSWORD`.
2. **Certificate (`.p12`).** Create `~/rclick-secrets` (mode 700), generate a random password file. `security export -k ~/Library/Keychains/login.keychain-db -t identities -f pkcs12 -P "$(cat pw)" -o all.p12` (owner clicks Allow; it exports EVERY identity, including development ones). Filter to the Developer ID identity only: `openssl pkcs12 -in all.p12 -nodes` → pick the cert whose subject contains `Developer ID Application` and the private key with the same modulus → `openssl pkcs12 -export` to `devid.p12`; delete `all.p12` and the pem at once. Verify before writing: import `devid.p12` into a scratch keychain and require exactly one `Developer ID Application` identity (`security find-identity -v -p codesigning`), then delete the scratch keychain. Write the secrets (`base64 -i devid.p12 | tr -d '\n' | gh secret set …`, password with `tr -d '\n' <pw | gh secret set …`), then delete `devid.p12`, the password file and the directory.
3. **Developer ID profiles (verified).** In a scratch copy (`git archive HEAD | tar -x -C /tmp/…`), under the heavy lock: `xcodebuild archive -project RClick.xcodeproj -scheme RClick -configuration Release -destination 'generic/platform=macOS' -archivePath … DEVELOPMENT_TEAM=GRT84NAK4T CODE_SIGN_STYLE=Automatic ARCHS=arm64 -allowProvisioningUpdates`, then `xcodebuild -exportArchive -exportOptionsPlist <method developer-id, teamID GRT84NAK4T, signingStyle automatic, signingCertificate "Developer ID Application"> -allowProvisioningUpdates`. Xcode (signed in as the owner) creates two "Mac Team Direct Provisioning Profile" entries in the developer account (ask the owner first: it changes their Apple account) and embeds them: `out/RClick.app/Contents/embedded.provisionprofile` and `…/PlugIns/FinderSyncExt.appex/Contents/embedded.provisionprofile`. Check with `security cms -D -i` the same facts the workflow checks (application-identifier, team, group, no `ProvisionedDevices`, certificate SHA-1 equals the identity's hash). Write both secrets with `base64 -i … | tr -d '\n' | gh secret set …`; delete the scratch directory. Fallback if Xcode refuses: owner creates Developer ID profiles at developer.apple.com (Profiles, one per App ID, group enabled on both App IDs).
4. **Release preconditions.** `git fetch --tags --force`; head green; `sh scripts/release/check-notes.sh <version>` passes; `git diff --name-only <tested-sha> <head>` shows only the paths the readiness doc allows; `gh release list` and `gh run list` show no release, draft or run in progress for the tag.
5. **Tag.** First tag: `git tag -a vX.Y.Z <head> && git push origin vX.Y.Z`. Retag of a never-released tag (owner approval): `git push origin :refs/tags/vX.Y.Z`, `git tag -d vX.Y.Z`, tag the merged head, push; never "Re-run" the pre-deletion run (it rebuilds the old commit with the old workflow).
6. **Watch** the run (a Monitor on `gh run view <id> --json status,conclusion,jobs`), step by step: tag/notes guards, certificate import, profile check, build, code sign, notarize app, staple, DMG, notarize DMG, App ZIP, Create Release. On failure: `--log-failed`, classify secret vs workflow, fix the secret, then `gh run rerun <id> -R anzchy/RClick --failed` if the rerun rules above hold.
7. **Check the draft** (read-only): `gh release view <tag> --json isDraft,isPrerelease,targetCommitish,assets` (draft true, prerelease false, DMG + zip + `.sha256`); body equals `docs/release/<version>-notes.md` (a trailing blank line is fine). Download into an empty `mktemp -d` and run: `shasum -a 256 -c`, `hdiutil verify`, `xcrun stapler validate` (DMG and app), `spctl -a -t open --context context:primary-signature -v <dmg>`, `spctl -a -vv <app>` (expect `source=Notarized Developer ID`), `codesign --verify --deep --strict`, Info.plist version; delete the directory.
8. **Owner:** clean-machine install and #40 on the draft, then Publish. **Delegator after Publish:** update-check smoke test, ledger/metrics, milestone.

## Known leftovers and tips
- A scratch archive or export may register a build with LaunchServices/pluginkit; check `pluginkit -mAvvv -i cn.anzchy.RClick.FinderSyncExt` afterwards and have the owner `lsregister -u` stale paths.
- Installing the DMG on a machine that had the upstream app: the new app is a different identity (`cn.anzchy.RClick`); if the Finder menu is missing, check `pluginkit -mAv -p com.apple.FinderSync` shows `+`, eject the DMG, unregister old copies in the Trash, restart RClick and Finder.
- Finder shows each FinderSync extension's items as one group in extension registration order; there is no API to place them. Toggling other extensions with `pluginkit -e ignore/use` moved RClick above WPS on the owner's MacBook (see the memory note); ask first.
