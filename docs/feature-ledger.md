# RClick feature ledger

The hand-inspected inventory of every feature RClick ships today. **Verified against `e729e01`** (#49's code, rebased on main
`453241c`, 2026-11-20) by reading the code, the specs, and the issues and PRs on `anzchy/RClick`: at `e729e01` the
files #49 changed and the blocks that cite them were re-read; every other block carries the full read at `38d356a`,
whose code `453241c` keeps (`git diff 38d356a 453241c` touches only `docs/` and one delegator brief template). Nothing here was checked by running the
app for this ledger. Device results are cited from public evidence on `anzchy/RClick` (see Device runs cited); a run
id in parentheses only points at the roster's private record, which a reader never needs.

This is the **qualitative half** of the ledger. The quantitative half is `docs/feature-metrics.md`, generated by
`node scripts/feature-ledger/gen-feature-ledger.mjs` from the spine `docs/feature-ledger/feature-map.json`. Sizes,
test counts, last touch, churn and CHANGELOG mentions live there; this file cites those cells as
*metrics `<feature id>` › `<column>`* and never copies a number. Who updates what, and when:
`docs/agents/feature-ledger.md`.

## How to read a block

| Field | Meaning |
|---|---|
| heading | the spine id, which is also the row in `docs/feature-metrics.md` |
| What | what the user gets |
| Status | tags from the vocabulary below |
| Default | the shipped default, with the line that sets it |
| Reached | how a user gets to it (menu item id, Settings tab, automatic) |
| Runs in | the process (the spine's `process`), and where the work actually happens |
| Code | entry points that matter, as repo paths |
| Tests | which tests pin it, and what no test pins; counts are in the metrics row |
| Specs, issues, PRs | linked documents on disk and on `anzchy/RClick` |
| Device | PASS (public evidence, then the run id), NOT VERIFIED (reason), UNVERIFIED by this ledger (private record), or never run |
| Gaps | what is known to be broken, unwired or unverified, each with its source |

A claim that no source settles is marked **UNVERIFIED** in place, never guessed.

## Status vocabulary

| Tag | Meaning |
|---|---|
| `shipped-on` | reachable in a default install |
| `shipped-off` | complete, but behind a default-off setting |
| `partial` | reachable, but a named sub-capability is missing or broken |
| `unwired` | code or a setting exists and nothing in production reaches it |
| `infrastructure` | no menu item or Settings control of its own; features stand on it |

## Open findings

Each finding names the feature block that carries the detail and at least one source. When a finding is fixed,
delete its line in the same change.

1. `open-with`: `AppPresets.resolveOpenTargets` (`Shared/AppPresets.swift:120`) applies `removingPercentEncoding` to
   each target path, and `ActionService.openApp` (`RClick/Runtime/ActionService.swift:132-134`) passes it the
   clicked Finder paths, so an item whose name holds a literal `%xx` is opened under a different path. PR #29's
   description lists this line as decoding "app config values, not Finder paths"; the call site passes click
   targets. No test covers a percent name for Open With; the device result is **UNVERIFIED**. No issue filed yet.
2. `delete-direct`, `hide`, `unhide`, `airdrop`, `open-with`, `common-dirs`: `ActionService` interpolates target
   paths into log calls (for example `RClick/Runtime/ActionService.swift:129`, `:186`, `:742`, `:792`, `:990`) with
   no `privacy:` argument. Issue #39. Whether they reach the persisted log unredacted is **UNVERIFIED** (the
   `@AppLog` wrapper, `RClick/Shared/AppLogger.swift`, returns a plain `os.Logger`).
3. `ipc`: the first creation of the per-install key on a fresh macOS user account with a release-signed build is a
   release gate nobody has run (issue #40). Follow-ups left open by #6: a clock barrier seen only by the extension
   retires the session the app still uses (M1), the retired-session history is capped and never evicts (M2), and
   the Lows listed there (issue #41).
4. `cut`: a new-session `running` announcement can leave a captured "Cut enabled" state for one render without a
   current config; a failure to read an item's identity or to write the pasteboard is only logged
   (`RClick/Runtime/ActionService.swift:713-719`); the production caller `FinderSyncExt.makeActionItem` has no test.
   Issue #42.
5. `paste-move`: the destination is re-checked by its lexical path inside the coordinated block, so swapping an
   ancestor of the destination for a symlink can land an item in a trashed folder or a package
   (`RClick/Runtime/PasteMoveEngine.swift`). Issue #48 names it a release blocker for any build containing Paste,
   together with #10, #11 and #12.
6. `paste-move`, `connection-state`, `new-file`: from the issue #12 device run: Paste (move here) is offered on a
   selected file's menu and then refuses; a cut item deleted before Paste is reported with the raw system message,
   and the clipboard then keeps the marker but no file URL; with RClick offline the New File submenu stays enabled;
   files created by New File carry a quarantine attribute. Issue #53.
7. `new-file`, `new-file-settings`: a custom type whose extension was typed without a dot creates `Untitled<ext>`:
   the sheet stores the field verbatim and `ActionService.getUniqueFilePath`
   (`RClick/Runtime/ActionService.swift:1100-1114`) appends the extension with no dot. Issue #51 (device FAIL in the
   issue #12 comment).
8. `settings-backup`, `menu-layout`: importing a backup does not restore `foldActionsMenu` (issue #52, observed on
   the device). `SettingsBackup.Preferences.apply` (`RClick/Runtime/SettingsBackup.swift:260-262`) writes that key, so
   the cause is **UNVERIFIED**; which other preferences import skips is unchecked (issue #52).
9. `apps-settings`: Settings > Apps > Edit stores Run Arguments and Environment Variables
   (`RClick/Settings/EditAppSheetView.swift`, persisted by `RClick/Runtime/ConfigService.swift` and
   `RClick/Runtime/SettingsBackup.swift`), but `ActionService.openWithApp` and `openRetryAfterPermission`
   (`RClick/Runtime/ActionService.swift:153-155`, `:175-176`) set only `createsNewApplicationInstance` on
   `NSWorkspace.OpenConfiguration`, so they have no effect. No issue filed yet.
10. `new-file-settings`: Edit File Type stores a Default Open App (`RClick/Settings/EditFileTypeSheetView.swift`,
    `NewFile.openApp` in `Shared/RCBase.swift`); `ActionService.createFile` never reads it. No issue filed yet.
11. `new-file`: `NewFileMenuItem.customFileId` (`Shared/RCBase.swift:404`) has a branch in `ActionService.createFile`
    (`RClick/Runtime/ActionService.swift:1017-1032`) that creates an extension-less file, but
    `MenuService.buildConfig` (`RClick/Runtime/MenuService.swift`) never emits that item; only
    `ActionServiceTests.newFilePreservesRawPercentTarget` reaches it. No issue filed yet.
12. `update`, `about`: **RESOLVED by #57.** The update checker and star count used to read the upstream repository
    `wflixu/RClick` (`RClick/RClickApp.swift:40`); the checker now reads `anzchy/RClick` (`UpdateSource` in
    `RClick/Shared/Updater.swift`), the star count and its fetch are removed, and the About tab carries one
    attribution sentence.
13. `hide`, `unhide`: neither acts on "the selected items" as the device recipe `ACT-03` describes.
    - Hide (`RClick/Runtime/ActionService.swift:836-905`, `hideFilesAndDirs`) branches on the menu trigger. On items
      (`ctx-items`) it hides each selected item. On the window background (`ctx-container`) it hides every item
      directly inside the **first target**, not the target itself. On the toolbar or sidebar it does nothing.
    - The target list of every action click except Paste is `selectedItemURLs()` only, with no `targetedURL()`
      fallback (`FinderSyncExt.handleActionClick`, `FinderSyncExt/FinderSyncExt.swift:632`, `:651`; `handleAppClick`
      falls back at `:681-683`). So on the window background Hide's first target is the first *selected* item, if
      there is one, not the folder clicked in. What Finder returns there is **UNVERIFIED** pending a device run.
    - Unhide (`ActionService.swift:791-834`, `unhideFilesAndDirs`) ignores the trigger and every target but the
      first. It clears the hidden flag on each item directly inside the first target (for a file the listing throws
      and is only logged, `:819-820`), then on the first target itself (`:823-831`).
    - Whether this is the intended design is **UNVERIFIED**; no spec says.
14. `finder-menu` (tooling): the device skill's `finder-menu.sh` and `axdump.sh` cannot see Finder's context menu on
    this macOS and `panel-choose.sh` needs the ABC input source (issue #26); `ui.sh grant` fails on the open panel
    (issue #38); the problems collected by the issue #12 run, including no Cut or Paste recipe in `features/`
    (issue #54).
15. `new-file`: a click without an entry id (an extension older than the template list, whose menu items carry no
    entries) picks Blank when it is on, else the first enabled template, and refuses with the warning when that
    template's file is missing even if a later enabled template exists (`RClick/Runtime/ActionService.swift:1053-1062`).
    The menu the current app sends lists only templates whose file exists (`RClick/Runtime/MenuService.swift:29`).
    No issue filed yet.
16. `new-file`, `new-file-settings`, `settings-backup`, `persistence`: template snapshots that nothing removes.
    - Import saves with `preserveTemplateSnapshots: true` (`RClick/Settings/GeneralSettingsTabView.swift:350`), so the
      snapshots of the entries an import replaces stay in the Templates folder (`RClick/Runtime/ConfigService.swift:193`).
    - Save writes new and replacement snapshots before the database save (`RClick/Settings/EditFileTypeSheetView.swift:247`,
      `TemplateDraft.save`). When the database save fails it rolls back (`ConfigService.swift:190-191`), but
      `AppState` keeps the updated `newFiles` (`AppState.persist` only sets `lastSaveError`), so the next successful
      save in the same session persists the fresh copy and deletes a replaced one (`ConfigService.swift:194-196`).
      Only a relaunch before that save leaves the fresh copy unreferenced. Cleanup only looks at paths a stored entry
      referenced (`:161-164`), so neither an import's leftover nor such a copy is removed later.
    - When one of several snapshot writes fails, the sheet stays open (`EditFileTypeSheetView.swift:221-223`) and the
      copies already written are not referenced; a second Save writes them again under a fresh name
      (`TemplateStore.write`, `RClick/Runtime/TemplateStore.swift:52-55`), so the first copies stay unreferenced.
    - A snapshot deletion that throws after the database save succeeded (`ConfigService.swift:195-197`) is reported
      through `AppState.lastSaveError` as a failed save, although the settings were saved.
    No issue filed yet.
17. `settings-backup`: the "N templates not included" count after an import does not match what the import kept.
    `importOmittedTemplateCount` (`RClick/Runtime/SettingsBackup.swift:226-232`) calls `toModel` without the current
    entries, while `applyImport` passes them (`RClick/Settings/GeneralSettingsTabView.swift:343-347`), so an entry
    re-attached to its adopted pre-#49 path on the same Mac is counted as not included. A backup in the older
    one-path format counts its template whether or not the file exists here (`SettingsBackup.swift:229`). No issue
    filed yet.
18. `settings-backup`: `TemplateStore.snapshotPath` (`RClick/Runtime/TemplateStore.swift:17-28`) takes the first
    owned child of the entry's folder in name order and does not skip hidden files, so it can re-attach an entry to a
    `.DS_Store` or to a leftover copy from finding 16. Whether a hand-edited backup whose template id differs from
    the folder name only in letter case finds its snapshot is **UNVERIFIED** (it depends on the case
    `resolvingSymlinksInPath` returns, `TemplateStore.owns`, `:70-84`). No issue filed yet.
19. `new-file`, `finder-menu`: the tag-routing test builds the delivered `NSMenuItem` itself
    (`RClickTests/MultiTemplateMenuTests.swift:59-66`); the extension's private `makeNewFileItem`
    (`FinderSyncExt/FinderSyncExt.swift:567-590`) and its click handler (`:696-710`) run in no test. Finder's delivery
    of direct and type-submenu leaves PASSed on the device at `e729e01` (issue #49 comment); no test would catch a
    later change to that code. No issue filed yet.
20. `new-file-settings`: Restore Defaults on the New File tab replaces every type at once and, once that save has
    persisted, deletes every owned snapshot a stored entry referenced, with no confirmation
    (`RClick/Settings/NewFileSettingsTabView.swift:38-39`, `AppState.resetFiletypeItems`, `RClick/AppState.swift:201-204`;
    the rule in `persistence`, `RClick/Runtime/ConfigService.swift:160-197`). Copies no stored row referenced (finding
    16) and files outside the Templates folder are not deleted. CHANGELOG [Unreleased] › Changed states the deletion;

    the missing confirmation accepted. Delete File Type and Reset All Settings ask first
    (`NewFileSettingsTabView.swift:117-133`, `RClick/Settings/GeneralSettingsTabView.swift:408-421`). No issue filed yet.

## Finder menu: Actions

### `copy-path`
- **What:** puts every selected item's full path on the pasteboard, one per line, in one plain-text-only
  pasteboard item, keeping literal characters such as `%xx` (`Shared/Clipboard.swift` `copyPaths`; CHANGELOG
  [Unreleased] › Changed, › Fixed). Finder's Command-C copies files; Copy Path does not enable Finder file paste.
  Embedded newlines in names are preserved, making the line-separated text ambiguous for those names.
- **Status:** `shipped-on`.
- **Default:** on (`Shared/RCBase.swift` `RCAction.copyPath`, `enabled: true`).
- **Reached:** Finder menu, action id `copy-path`, on items, container, sidebar and the toolbar button.
- **Runs in:** the extension only. `FinderSyncExt.handleActionClick` copies locally and sends no IPC
  (`FinderSyncExt/FinderSyncExt.swift:636-639`), and the item stays enabled while RClick is offline (`:548`).
  `ActionService.copyPath` exists but no click reaches it.
- **Tests:** `ClipboardTests` (one text-only item, single and multiple paths, literal bytes, empty selection) and
  `ActionServiceTests.copyPathAndFileNameWriteToTheInjectedPasteboard`; metrics `copy-path` › Test cases.
- **Issues, PRs:** #25, #28; PR #27 (injected pasteboard), PR #34 (literal percent sequences), PR #46 (text-only).
- **Device:** PASS single and multi-selection (PR #23 › Device at `ed3ef56`, PR #27 › Device at `cfec391`; runs
  `i22-device-20261116e`, `i13-device-20261117c`, private records). PASS literal percent names, one path per line
  (PR #34 › Device at `78a1fc6`; run `i28-i32-device-20261118`). At `38d356a` (issue #12 comment; run
  `i-device-20261120`): PASS one plain-text item of one type; PASS pasted into a text field; PASS Finder's Edit >
  Paste stays disabled; PASS no CFPasteboard sandbox lines in either log; observed offline: Copy Path stays enabled
  and still copies. NOT VERIFIED: pasted into a terminal (issue #12 comment).

- **What:** permanently deletes the selection (not to the Trash) after a confirmation; with Option held while the menu

- **Status:** `shipped-on`.
- **Default:** on (`Shared/RCBase.swift` `RCAction.deleteDirect`).
- **Reached:** Finder menu, action id `delete-direct`.
- **Runs in:** the app, over IPC. The batch runs on `ActionExecutor` off the main thread while an `AccessLease` keeps

- **Tests:** the `delete…`, `optionClick…`, authorization and partial-failure cases in `ActionServiceTests`
  (including `deletePreservesRawPercentSelection`), `ProtectedFolderTests` and
  `FileOperationsTests.removeDeletesTheItem`; metrics `delete-direct` › Test cases.
- **Specs, issues, PRs:** `specs/bug-direct-delete-option-state.md`; #5, #6, #13, #39; PR #27, PR #29.
- **Device:** PASS confirmation, cancel, confirm and the Option variant, on a file and on a folder (PR #23 › Device);
  multi-selection of two files and a folder under one alert, a partial failure (the others removed, the unremovable
  item kept, the failure only logged), large batches with Finder and RClick responsive (PR #27 › Device) (runs
  `i22-device-20261116e`, `i13-device-20261117c`, private records). PASS on literal percent sibling pairs: only the
  selected item removed, with and without confirmation (PR #29 › Device at `971b658`; run `i5-device-20261117d`).

### `cut`
- **What:** marks the selected items as a pending cut without touching them: RClick writes their file URLs, the
  marker type `cn.anzchy.RClick.cut` and the source tag `org.nspasteboard.source` to the general pasteboard as
  current-host-only (`Shared/PendingCut.swift` `writeCut`), then records each item's identity and the pasteboard's
  change count (`RClick/Runtime/ActionService.swift:667-723`, `prepareCut`). Before writing, it asks for folder
  access to each source's parent, then refuses a selection holding a protected folder, or on a read-only volume or
  in an unwritable folder, with a message in the shared warning window. Any later pasteboard write ends the cut.
  CHANGELOG [Unreleased] › Added: "Opt-in Cut action marks selected Finder files as a pending cut locally without
  changing files".
- **Status:** `shipped-off`.
- **Default:** off: Settings > Actions lists it as "Cut & Paste" (`Shared/RCBase.swift:224` `RCAction.cut`,
  `enabled: false`; `RClick/Model/ActionEntity.swift:56`; an older store gains the row switched off,
  `ActionBackfillTests.cutBackfillsOffWithoutChangingExistingOrderOrToggles`).
- **Reached:** Finder menu on selected items only, titled "Cut", once enabled; never on the window background, the
  sidebar or the toolbar menu (`Shared/PendingCut.swift` `menuVisibility`, `FinderSyncExt/FinderSyncExt.swift:377-390`).
  Inline, or under "Actions" when the actions menu is collapsed.
- **Runs in:** extension and app. The extension decides visibility and disables the item while RClick is offline
  (`PendingCut.renderCutEnablement`, `FinderSyncExt/FinderSyncExt.swift:546-547`); the click travels as a `.click`;
  `ActionService.actionHandler` (`RClick/Runtime/ActionService.swift:218-231`) refuses it unless the stored action is
  enabled, the trigger is the items menu and the selection is non-empty. The app pushes the pending cut's change
  count and item count in the menu config (`RClick/Runtime/MenuService.swift`, `RClick/RClickApp.swift:304-306`).

### `ipc`
- **What:** `DistributedNotificationCenter` messages on the fork's own channels, `cn.anzchy.RClick.ExtensionToMain`
  and `cn.anzchy.RClick.MainToExtension` (`Messager.extensionToMainNotification`, `mainToExtensionNotification`,
  `Shared/Messager.swift:197-198`): extension → app `click`, `heartbeat`, `request-config`; app → extension
  `menu-config` (with the pending cut's counts), `running`, `quit`, `action-ack`.
  A `menu-config` New File item may carry its entries (id and name) and a `click` the chosen entry's `templateId`;
  both fields are optional, so a message without them still decodes (`NewFileMenuItem.entries`,
  `Shared/RCBase.swift:431`; `ClickEventPayload.templateId`, `Shared/Messager.swift:131`). The extension finds the
  chosen leaf from its menu item tag, a hash of the length-prefixed type id and entry id, because Finder keeps the tag
  and drops `representedObject` (code comment, `NewFileMenuItem.leafTag`, `Shared/RCBase.swift:415-419`; not observed
  on a device); an unknown or ambiguous tag sends no click (`selection(forTag:in:)`, `:421-429`;
  `FinderSyncExt/FinderSyncExt.swift:696-701`). The app hands `templateId` to `createFile`
  (`RClick/RClickApp.swift:332`).
  Every message is an authenticated envelope (`Shared/MessageSecurity.swift`): an HMAC over every field with a
  per-install key that the app creates in the shared Keychain access group and the extension only reads
  (`Shared/IPCKeyProvider.swift`); the app's launch session, which every click must carry; a timestamp checked for freshness; a nonce
  checked against replay; a clock-step barrier that retires the session; menu configs that cannot move backwards
  within a session. A click whose ack was not posted, or whose session rotated before dispatch, is dropped (PR #44).
  After unverifiable messages are rejected the menu bar item shows a notice (`IPCRejectionNotice`,
  `RClick/MenuBarView.swift:52-54`).
- **Status:** `infrastructure`.

  `MessageSecurity` has no field list to update (`Shared/MessageSecurity.swift:23-24`).
