# RClick feature ledger

The hand-inspected inventory of every feature RClick ships today. **Verified against `d63c29c`** (main on 2026-11-17)
by reading the code, the specs, the issues and PRs on `anzchy/RClick`, and the device validation records of the
herdr roster. Nothing here was checked by running the app for this ledger; device results are quoted from the named
runs.

This is the **qualitative half** of the ledger. The quantitative half is `docs/feature-metrics.md`, generated by
`node scripts/feature-ledger/gen-feature-ledger.mjs` from the spine `docs/feature-ledger/feature-map.json`. Sizes,
test counts, last touch, churn and CHANGELOG mentions live there; this file cites those cells as
*metrics `<feature id>` › `<column>`* and never copies a number. Who updates what, and when:
`docs/agents/feature-ledger.md`.

## How to read a block

| Field | Meaning |
|---|---|
| heading | the spine id, which is also the row in `docs/feature-metrics.md` |
| What | what the user gets |
| Status | tags from the vocabulary below |
| Default | the shipped default, with the line that sets it |
| Reached | how a user gets to it (menu item id, Settings tab, automatic) |
| Runs in | the process (the spine's `process`), and where the work actually happens |
| Code | entry points that matter, as repo paths |
| Tests | which tests pin it, and what no test pins; counts are in the metrics row |
| Specs, issues, PRs | linked documents on disk and on `anzchy/RClick` |
| Device | PASS (run id), NOT VERIFIED (reason), or never run |
| Gaps | what is known to be broken, unwired or unverified, each with its source |

A claim that no source settles is marked **UNVERIFIED** in place, never guessed.

## Status vocabulary

| Tag | Meaning |
|---|---|
| `shipped-on` | reachable in a default install |
| `shipped-off` | complete, but behind a default-off setting |
| `partial` | reachable, but a named sub-capability is missing or broken |
| `unwired` | code or a setting exists and nothing in production reaches it |
| `infrastructure` | no menu item or Settings control of its own; features stand on it |

## Open findings

Each finding names the feature block that carries the detail and at least one source. When a finding is fixed,
delete its line in the same change.

1. `new-file`: only `template.xlsx` is bundled (`RClick/Resources/template.xlsx`); DOCX, PPTX, Pages, Keynote and
   Numbers fall back to a 0-byte file (`RClick/Runtime/ActionService.swift` `createFile`, log "模板文件不存在").
   Issue #24; seen on device in `i22-device-20261116e`.
2. `copy-path`, `copy-file-name`: `Shared/Clipboard.swift:11` and `:31` apply `removingPercentEncoding` to raw
   Finder paths, so a name holding a literal `%xx` is copied wrong. Issue #28. The unit test
   `ClipboardTests.copyPathsDecodesPercentEncoding` pins the decoding as intended behaviour, so fixing #28 changes
   that test.
3. `delete-direct`, `hide`, `unhide`, `airdrop`, `common-dirs`, `new-file`: `RClick/Runtime/ActionService.swift`
   lines 134, 190, 244, 290, 323, 371 and 543 decode percent sequences in the paths they act on. Run
   `i5-device-20261117b` (PR #29 head, not main) saw Delete Direct remove the decoded sibling (`%44ocuments`
   instead of `%2544ocuments`); its record leaves the root cause open (possibly upstream of `ActionService`).
   Main's behaviour on such names is **UNVERIFIED** on a device. Issue #5, PR #29 (open).
4. `delete-direct`, `hide`, `airdrop`: the protected-folder check never matches. `Utils.isProtectedFolder`
   (`RClick/Shared/Utils.swift`) compares with plain `==` against `Constants.protectedDirs`, whose entries end in
   `/`, while Finder paths do not; it also `print`s every comparison. Issue #5, PR #29 (open).
5. `ipc`: the HMAC key is a source constant (`Shared/MessageSecurity.swift:26`) and messages carry no nonce or
   timestamp, so any local process can forge or replay a `.click`. Issue #6.
6. `copy-path`: the extension logs "Sandbox extension creation failed … public.file-url" on Copy Path; the text
   still pastes, and whether the file-URL flavour pastes into Finder is **UNVERIFIED**. Issue #25, run
   `i22-device-20261116e`.
7. `localization`: the app logs missing-localization errors for TXT, Markdown, Pages, Keynote and Numbers. Issue #25,
   runs `i22-device-20261116e` and `i13-device-20261117c`.
8. `apps-settings`: Settings > Apps > Edit stores Run Arguments and Environment Variables
   (`RClick/Settings/EditAppSheetView.swift`, persisted by `RClick/Runtime/ConfigService.swift` and
   `RClick/Runtime/SettingsBackup.swift`), but `ActionService.openWithApp` (`RClick/Runtime/ActionService.swift`)
   passes neither to `NSWorkspace.OpenConfiguration`, so they have no effect. No issue filed yet.
9. `new-file-settings`: Edit File Type stores a Default Open App (`RClick/Settings/EditFileTypeSheetView.swift`,
   `NewFile.openApp` in `Shared/RCBase.swift`); `ActionService.createFile` never reads it. No issue filed yet.
10. `new-file`: `NewFileMenuItem.customFileId` (`Shared/RCBase.swift`) has a branch in `ActionService.createFile`
    that creates an extension-less file, but `MenuService.buildConfig` (`RClick/Runtime/MenuService.swift`) never
    emits that item, so nothing reaches it. No issue filed yet.
11. `update`: the update checker and star count read `wflixu/RClick` (`RClick/RClickApp.swift:38`), the upstream
    repository, not the fork whose identifiers #22 changed. Whether that is intended for the fork is **UNVERIFIED**.
    No issue filed yet.
12. `hide`: on the window background (`ctx-container`) Hide hides **every item in the folder**, not the folder; on
    the toolbar or sidebar it does nothing (`ActionService.hideFilesAndDirs`). `unhide` clears the flag on the
    contents of the first selected folder only, and fails on a selected file (`ActionService.unhideFilesAndDirs`).
    Whether this is the intended design is **UNVERIFIED**; the device recipe `ACT-03` describes it as acting on the
    selected items.
13. `finder-menu` (tooling): the device skill's `finder-menu.sh` and `axdump.sh` cannot see Finder's context menu on
    this macOS, and `panel-choose.sh` needs the ABC input source. Issue #26.

## Finder menu: Actions

### `copy-path`
- **What:** puts every selected item's full path on the pasteboard, one per line, plus file URLs so Finder can paste
  the files (`Shared/Clipboard.swift`; CHANGELOG [Unreleased] › Changed).
- **Status:** `shipped-on`, `partial` (findings 2 and 6).
- **Default:** on (`Shared/RCBase.swift` `RCAction.copyPath`, `enabled: true`).
- **Reached:** Finder menu, action id `copy-path`, on items, container, sidebar and the toolbar button.
- **Runs in:** the extension only. `FinderSyncExt.handleActionClick` copies locally and sends no IPC, so it also
  works while RClick is offline (`FinderSyncExt/FinderSyncExt.swift`, "快链路"). `ActionService.copyPath` exists but
  no click reaches it.
- **Tests:** `ClipboardTests` (text, file URLs, empty selection) and
  `ActionServiceTests.copyPathAndFileNameWriteToTheInjectedPasteboard`; metrics `copy-path` › Test cases.
- **Issues, PRs:** #25, #28; PR #27 (injected pasteboard).
- **Device:** PASS single and multi-selection (`i22-device-20261116e`, `i13-device-20261117c`). Offline Copy Path
  (`CONN-02`): NOT VERIFIED, not run. Literal-percent name: inconclusive in `i5-device-20261117b` (row uncertain).

### `copy-file-name`
- **What:** puts every selected item's name, without its path, one per line, and no file URLs
  (`Shared/Clipboard.swift` `copyFileNames`).
- **Status:** `shipped-on`, `partial` (finding 2).
- **Default:** on (`Shared/RCBase.swift` `RCAction.copyFileName`).
- **Reached:** Finder menu, action id `copy-file-name`.
- **Runs in:** the app: the extension sends a `.click` (`FinderSyncExt.handleActionClick`), `ActionService.actionHandler`
  runs it. Offline, the item is disabled (`FinderSyncExt.swift`, `isHostAppRunning` check).
- **Tests:** `ClipboardTests.copyFileNamesWritesOneNamePerLineAndNoFileURLs`, the shared `ActionServiceTests` pasteboard
  test, and `ActionBackfillTests.freshStoreSeedsCopyFileNameAfterCopyPath` (an upgraded store gains the action).
- **Issues, PRs:** #28; PR #27.
- **Device:** PASS single and multi-selection (`i22-device-20261116e`, `i13-device-20261117c`).

### `delete-direct`
- **What:** permanently deletes the selection (not to the Trash) after a confirmation; with Option held while the menu
  opens, the title reads "(skip confirmation)" and no dialog appears (`RClick/Runtime/DeleteConfirmation.swift`,
  `specs/bug-direct-delete-option-state.md`, CHANGELOG [Unreleased]).
- **Status:** `shipped-on`, `partial` (findings 3 and 4).
- **Default:** on (`Shared/RCBase.swift` `RCAction.deleteDirect`).
- **Reached:** Finder menu, action id `delete-direct`.
- **Runs in:** the app, over IPC. The batch runs on `ActionExecutor` off the main thread while an `AccessLease` keeps
  the covering bookmarks open (`RClick/Runtime/ActionExecutor.swift`, `RClick/Runtime/AccessLease.swift`, PR #27).
  Order: folder authorization first, then the confirmation (`ActionServiceTests.authorizationIsRequestedBeforeConfirmation`).
- **Tests:** the `delete…`, `optionClick…`, authorization and partial-failure cases in `ActionServiceTests` and
  `FileOperationsTests.removeDeletesTheItem`; metrics `delete-direct` › Test cases. No test covers the protected-folder
  check on main (#5).
- **Specs, issues, PRs:** `specs/bug-direct-delete-option-state.md`; #5, #6, #13; PR #27 (merged), PR #29 (open).
- **Device:** PASS confirm, cancel, Option skip, folder, multi-selection, partial failure (others removed, the
  unremovable folder kept, failure only logged), batch responsiveness (`i22-device-20261116e`,
  `i13-device-20261117c`). FAIL on percent-named siblings at the unmerged PR #29 head (`i5-device-20261117b`).
  NOT VERIFIED: protected folders (not attempted by design), access-lease revoke race (needs a Settings revoke during
  a batch, `i13-device-20261117c`).
- **Gaps:** a partial failure is only logged; the user sees no message (`i13-device-20261117c`).

## Finder menu: Open With

- **What:** creates `Untitled.<ext>` (or a numbered variant) in the clicked folder, or the folder of a clicked file,

- **Status:** `shipped-on`, `partial` (findings 1, 3, 10).

- **Reached:** Finder menu on items or the window background.
- **Runs in:** the app, over IPC; an ungranted folder prompts first.
- **Tests:** `ActionServiceTests.fileTemplateSurvivesSaveAndReload`,
  `SettingsBackupTests.missingTemplateFallsBackToTheBuiltInTemplate`. No test creates a file from a menu click.
- **Issues:** #24 (missing templates), #25 (localization of the type names).
- **Device:** PASS TXT (one file, one click event, no no-ack alert) and XLSX (bytes equal the bundled template)

  PASS in a percent-named folder and a CJK folder at the PR #29 head (`i5-device-20261117b`). PPTX, JSON, Pages,
  Keynote, Numbers: never run.

### `new-file-auto-rename`

- **Tests:** none (spine `tests: []`).

## Finder menu: presence

### `finder-menu`
- **What:** one RClick section in Finder's context menu for items, the window background and sidebar entries, built

  the first config arrives it shows "RClick (loading...)".

- **Default:** on once the extension is enabled in System Settings (`CLAUDE.md` › Common Issues).
- **Tests:** `MenuCompatibilityTests` (payload compatibility). Nothing tests menu construction itself.
- **Device:** PASS one RClick section on a file row (`i22-device-20261116e`, `i13-device-20261117c`). Folder,
  multi-selection, background and sidebar menus (`EXT-03` to `EXT-05`): never run as separate rows. Issue #26 tracks
  the tooling that cannot read the menu.

### `finder-toolbar-button`
- **What:** the RClick button in Finder's toolbar opens the same menu; apps hidden for the toolbar are absent there
  (`FinderSyncExt.toolbarItemName`, `AppMenuItem.isVisible(for: .toolbar)`).
- **Status:** `shipped-on`.
- **Default:** absent until the user adds the button to the toolbar.
- **Tests:** `MenuCompatibilityTests` covers the visibility flags only.
- **Device:** never run (`EXT-06` needs the owner to add the button).

### `menu-layout`
- **What:** per-section collapse switches (Settings > Apps / Actions / New File / Common Dir) and the app icon style
  in Open With (Settings > General > Icon Style: none, simple, original), with icon caches in both processes
  (`Shared/IconCache.swift`, `Shared/FileTypeIconProvider.swift`).
- **Status:** `shipped-on`.
- **Default:** apps and actions flat, new file and common dirs collapsed, simple icons (`RClick/AppState.swift`).
- **Tests:** `AppStateDefaultsMigrationTests` (the switches moved to the App Group store),
  `AppPresetsTests.symbolsReuseImagesWithinEachAppearance`.
- **Device:** never run as its own row; the default layout was what `i22-device-20261116e` saw (flat actions and
  Terminal, a "New File" submenu).

### `connection-state`
- **What:** the extension caches "last message from the app" for 30 s. Offline it greys the menu and adds "RClick is
  not running" / "Restart RClick to restore the menu"; clicking the hint relaunches RClick without opening Settings
  (`Shared/HintClickLaunch.swift`). A `.click` with no `.actionAck` within 3 s shows "RClick did not respond"; a
  `.quit` marks the app offline at once (`FinderSyncExt/FinderSyncExt.swift`, `CLAUDE.md` › Extension Development).
- **Status:** `shipped-on`.
- **Tests:** `PeerActivityTests` (the liveness cache). The alerts and the hint relaunch have no test.
- **Device:** PASS offline menu after quitting, once the 30 s cache expired (`i22-device-20261116e`,
  `i13-device-20261117c`); SIGTERM sends no `.quit`, so the menu stayed normal until then. NOT VERIFIED: hint
  relaunch (`CONN-03`), no-ack alert (`CONN-04`), offline click alert (`CONN-05`): not run.

### `observed-volumes`
- **What:** the extension observes the home folder and each mounted volume, updating on mount, rename and unmount
  without traversing them; external disks keep a drive icon in the sidebar (`Shared/MountedVolumeObserver.swift`,
  `RClick/Info.plist` declares the `externaldrive` symbol, `specs/external-volumes-observation.md`).
- **Status:** `shipped-on`.
- **Tests:** `MountedVolumeObserverTests`.
- **Device:** never run on an external volume.
